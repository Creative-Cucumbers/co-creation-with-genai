### 1. 学祭のことを話そう（講師用メモ・スライド掲載なし｜10分｜0〜10分）

学祭での展示や、誰かにアプリを使ってもらった経験を振り返りましょう。

- どんな反応がありましたか？
- 自分では気づかなかった使い方や、操作で迷う場面はありましたか？
- 次に作るなら、どこを変えたいですか？

展示に参加していない人は、学祭で印象に残った展示や体験から考えてみましょう。数人で話したあと、気になった気づきを全体で共有します。

### 2. これまでのアプリ開発を振り返ろう（30分｜10〜40分）

完成したかどうかに加えて、どんなやりとりや工夫が結果につながったかを振り返ります。うまく動かなかった経験も、次の制作のヒントになります。

| 時間 | 活動 |
| --- | --- |
| 5分 | 個人で振り返り、3つの質問にそれぞれSlack投稿（1人3投稿） |
| 10分 | 3〜4人で投稿を紹介し合い、つまずきやコツを話す |
| 10分 | 全体で投稿を眺め、共通するつまずきと解決方法を整理 |
| 5分 | 次の制作で試したいことを1つ、自分の投稿のスレッドに追記 |

**Slackには、以下の3つの質問にそれぞれ別のメッセージで投稿します（1人3投稿）。** 投稿時間は上記の最初の5分に含みます。短文でOKです。

#### 振り返り質問1｜思い通り・思った以上にできたこと

今までのアプリ開発で、思い通り、または思った以上にできたことは？
どのアプリで、何ができたかを具体的に書きましょう。

```text
【振り返り① できたこと】
アプリ名：
思い通り・思った以上にできたこと：
```

例：ToDoアプリで、PCで追加したタスクをスマホにも表示できた。

#### 振り返り質問2｜思い通りにいかなかったところ

今までのアプリ開発で、思い通りにいかなかったところは？
どのアプリで、何がうまくできなかったかを書きましょう。

```text
【振り返り② うまくいかなかったこと】
アプリ名：
実現したかったこと：
実際に起きたこと：
```

例：チャットアプリで履歴を残したかったが、再読み込みすると会話が消えてしまった。

#### 振り返り質問3｜アプリ開発しながら気づいたコツ

アプリ開発をしながら、どんなコツに気づきましたか？
役立った指示の出し方や、確認・修正の進め方を紹介しましょう。

```text
【振り返り③ 気づいたコツ】
気づいたコツ：
役立った場面・具体例：
```

例：一度に全部直そうとせず、変更を1つずつ頼んで操作を確認すると、問題の原因を見つけやすかった。

投稿後は3〜4人で紹介し合い、全体でも投稿を眺めます。「うまくいった」「難しかった」だけで終わらず、具体的な画面・指示・操作を紹介しましょう。解決していない問題も、そのまま相談してOKです。

最後の5分で、次に試したいことを自分の投稿のいずれかのスレッドに追記します。

### 3. 授業内容の総復習（20分｜40〜60分）

第2〜5回を各5分で振り返り、今回の制作にどう活かすかを整理します。道順の確認も、この20分に含めます。

#### 第2回｜伝え方で、AIの応答を変える（5分｜40〜45分）

**学んだこと**

- 明確性・制約・役割・手順分解と例示で、指示を具体化する。
- システムプロンプトで、チャットAIの役割・出力形式・語り口を整える。
- トークン・会話履歴・RAGなど、回答を生成する仕組みに触れた。

**今回の制作で活かすこと**

- 「誰向け・何をする・どんな条件か」を伝え、最初の機能を1つ作る。
- AIを組み込むなら、答え方と答えてほしくない内容も決める。
- 結果を見て指示を直し、操作→確認→修正を繰り返す。

例：「学生向けの相談AI。結論を先に、提案は3つ。情報が足りなければ質問して」

復習資料：[第2回 プロンプトエンジニアリング](../2_prompt_engineering/readme.md)

#### 第3回｜仕組みを知り、使う責任を考える（5分｜45〜50分）

**学んだこと**

- 学習と回答生成は別。AIは次のトークンを予測し、正しいとは限らない回答も作る。
- アプリは画面・サーバー・DB・LLMなどを組み合わせて動く。
- 合法性に加え、社会に受け入れられるかという観点でリスクを考えた。

**今回の制作で活かすこと**

- AIへ送る情報と保存する情報を整理し、個人情報や作品の権利に配慮する。
- 誤回答や情報流出で、誰が困るかを考える。
- AIの利用・限界・利用者への注意点を、画面や利用ルールで伝える。

問い：このアプリで問題が起きるとしたら？　技術の対策と、使い方のルールを両方考えよう。

復習資料：[第3回 AIの活用と倫理](../3_ai_ethics/readme.md)

#### 第4回｜保存とログインで、アプリを育てる（5分｜50〜55分）

**学んだこと**

- HTMLは構造、CSSは見た目、JavaScriptは動作。小さく作り、操作して確かめる。
- localStorageはブラウザ内、Firestoreはクラウドにデータを保存する。
- Authenticationでログインし、ToDoやチャット履歴の保存・同期を試した。

**今回の制作で活かすこと**

- 残したいデータと、誰が使うデータかを決める。
- 同じアカウントで再読み込み・別端末を試し、保存と同期を確認する。
- 別アカウント・未ログインでも試し、他人のデータが見えないか確認する。

不具合の相談は「操作手順・期待した結果・実際の結果・エラー表示」をセットで伝えよう。

復習資料：[第4回 アプリ生成①](../4_webapp_dev_with_ai/readme.md)

#### 第5回｜入力・表現・データの幅を広げる（5分｜55〜60分）

**学んだこと**

- 入力：マイクの音を波形として可視化した。
- 表現：音や操作に応じた反応を作り、見た目や動きを調整した。
- データ：外部APIから情報を取得して表示。PublishしたURLでの公開も確認した。

**今回の制作で活かすこと**

- 文字やボタン以外の入力が、体験に役立つか考える。
- 入力に対する反応を調整し、使った人に結果が伝わるようにする。
- 必要な外部データを選び、公開URLをほかの端末でも試す。

問い：自分のアイデアは「入力・表現・データ」のどこを工夫すると、もっと面白くなる？

復習資料：[第5回 アプリ生成②](../5_webapp_dev_with_ai2/readme.md)

### 5. 成績評価の基準・提出方法の説明（10分｜70〜80分）

#### 成績評価の基準（案・100点満点）

授業で扱った技術の活用と、作品としての工夫・動作を、次の8項目で評価する案です。配点は調整中です。

| 項目 | 配点案 | 確認する内容 |
| --- | ---: | --- |
| 1. Firestoreの活用 | 10点 | アプリのデータを保存し、読み出して画面や機能に反映できる |
| 2. Authenticationの活用 | 10点 | ログイン・ログアウトが動き、ログイン状態に応じた機能や表示がある |
| 3. マイク／カメラの活用 | 10点 | どちらか、または両方から入力を取得し、アプリの機能や表現に活かしている |
| 4. Gemini APIの活用 | 10点 | アプリからAPIを呼び出し、応答を機能や体験に活かしている |
| 5. デプロイ・公開 | 10点 | 公開URLから、ほかの人がアクセスして利用できる |
| 6. UI／UXのこだわり | 15点 | 見た目や操作の流れに意図があり、使う人が迷わない工夫がある |
| 7. アイデアのこだわり | 15点 | 誰にどんな体験を届けたいかが明確で、選んだテーマや機能に自分なりの工夫がある |
| 8. アプリの動作 | 20点 | 目的に沿った主な操作を、開始から結果まで実演できる |
| **合計** | **100点** | |

技術の項目は、設定したことに加えて、アプリ内で実際に使えているかを確認します。Gemini APIの活用は、開発時にAIへコード生成を頼むこととは別です。マイクとカメラは、どちらか一方でも評価対象とします。

各項目は、**未実装／実装に取り組んだが動作が不十分／動作し目的に沿って活用できている**の段階で確認する想定です。UI／UXとアイデアは、作品の画面・操作に加え、制作ドキュメントに記載した意図や改善内容も参考にします。

制作時には、使う人とアプリの目的を考えて機能を選びましょう。フィードバックを受けて何を改善したかも、工夫を説明する材料になります。

### 7. 制作・実装タイム（60分｜0〜60分）

3限に決めたアイデアをもとに制作します。最初に作る機能を確認してから始めましょう。

| 時間の目安 | 進めること |
| --- | --- |
| 0〜5分 | 目的・最初に作る機能を確認し、AIへの指示を整理 |
| 5〜40分 | 作成・操作確認・修正を繰り返す |
| 40〜55分 | 他の人に試してほしい操作ができるか確認 |
| 55〜60分 | 動いた版を保存し、体験用のURLや端末を準備 |

- 変更する前の状態を残し、機能は1つずつ追加しましょう。
- つまずいたら、何をしたときに何が起きたかを整理して相談しましょう。
- 未完成でも、試せる部分を用意しましょう。まだ動かない場合は、画面や実現したい操作を見せて相談できます。
- 試した指示や工夫は、制作ドキュメント用にメモしておきましょう。

### 8. お互いのアプリを使ってみよう（30分｜60〜90分）

全体での中間発表の代わりに、2人1組でアプリを使い合います。1ラウンド10分、相手を替えて3ラウンド行います。人数が奇数の場合は1組を3人にし、交代時間も含めて進めます。

#### 1ラウンドの進め方（10分）

| 時間 | 活動 |
| --- | --- |
| 0〜4分 | AのアプリをBが操作し、気づきを伝える |
| 4〜8分 | BのアプリをAが操作し、気づきを伝える |
| 8〜10分 | 各自でメモし、次の相手に交代 |

作者は最初に「誰向けのアプリか」「何を試してほしいか」を短く伝え、そのあとは相手の操作を観察します。

#### フィードバックの観点

- **よかったところ**：どの操作・表現がよかったか。
- **迷ったところ**：何をしようとして、どこで止まったか。
- **改善のアイデア**：どう変えると使いやすいか、もっと面白くなるか。

「使いにくい」だけで終わらず、「保存できたかわからなかったので、完了の表示があると安心」のように、具体的な場面と案を伝えましょう。

**受け取ったフィードバックのメモ**

```text
試してもらった操作：
よかったと言われたこと：
迷った・動かなかったところ：
もらった改善アイデア：
取り入れたいこと・その理由：
```
