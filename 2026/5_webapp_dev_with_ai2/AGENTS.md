# 第5回の授業資料の作成・編集

第5回の `readme.md` は、構造を[第2回](../2_prompt_engineering/readme.md)、説明・演習の書き方を[第4回](../4_webapp_dev_with_ai/readme.md)、授業内容と進行を[第5回のrunbook](lecture05_runbook.md)に合わせる。親ディレクトリの `AGENTS.md` と [DESIGN.md](../../DESIGN.md) の方針も守る。ユーザーの明示的な指示を優先する。

## 見出しの構造

- `#` は授業タイトルとして冒頭に1つ置く。
- 冒頭に授業イメージ画像、全7回の授業スケジュール、`### 目次` と `[TOC]` を置く。
- `##` は授業の時間帯の区切りと、番号付きの大項目に使う。
- `###` は1-1, 1-2などとナンバリングし、1の項目を分けた中項目。時間も掲載。
- `####` はスライド単位。
- 大項目・スライドには所要時間を付ける。
- 第4回のようにスライド1枚ごとのタイトルをすべて `##` にする構成は引き継がない。

## 冒頭のテンプレ
- タイトル
- スライドリンク：[スライドを開く](index.html)
- 全7回の授業スケジュール
- [TOC]
- 今日の道順
- （内容に入っていく）

## 説明と演習の書き方は第4回に合わせる

- 学生に直接伝わる、短く具体的な文章にする。
- 「まず作る → 試す → 仕組みを知る → 改良する」の流れを大切にする。
- 抽象的な説明には、身近な例・比較表・図を添える。
- AIへの指示例は、そのまま入力できるコードブロックで示す。
- 演習には、何をするか・何ができれば完了か・何を提出するか・何分使うかを書く。
- Slack投稿は、画面・短文・投稿例など、提出内容を具体的に示す。投稿時間は演習時間に含める。
- うまく動かない場合も、操作・現象・エラーを記録し、修正や理解につなげられる案内にする。
- DESIGN.mdに沿って、後でスライド化しやすい情報量とまとまりにする。
- 画像・図には説明や出典を付け、ローカル画像は原則 `images/` を参照する。
